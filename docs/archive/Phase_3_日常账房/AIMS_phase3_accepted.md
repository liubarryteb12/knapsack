## 一、 全局北极星与架构铁律（固定框架，留有扩展空间）

### 1.1 产品终极定位
**本地优先的模块化个人生活系统（Local-First Modular Life OS）**。采用 **“宿主微内核 + 共享能力引擎 + 可插拔业务模块 (Mod)”** 三层插座架构：
- **宿主层 (`src/core/`)**：IndexedDB 本地存储、主题外观、全局备份、模块开关注册表 (`ModRegistry`)。
- **共享引擎层 (`src/engines/`)**：
  - `LedgerEngine`（通用记账、分类、分摊、消费成分结构占比计算）
  - `TimelineEngine`（跨天行程、单日时间轴计划、50步撤销栈）
  - `NoteEngine`（结构化备忘录、每日复盘模板、自动保存）
  - `LanShareEngine`（手机安装 App 后的面对面局域网扫码分享与组团）
- **业务模块层 (`src/mods/`)**：按需插拔，界面统一，数据默认隔离、支持按需跨模块联动。

### 1.2 全局禁区（负面清单 / Anti-Goals）
- 🚫 **绝不碰金融与资金流**：只做纯数字记录、清结算建议与消费成分分析，不接任何支付接口。
- 🚫 **绝不搞云端与重型服务端**：100% 本机存储，无账号、无遥测。
- 🚫 **停止过度设计团队拓扑**：团队协作仅作为“手机装好 App 后面向亲友的面对面扫码组团工具（隶属旅行模块）”。**严禁**再往“家里放手机当算力主机、外网远程控制、复杂离线文件传输”方向投入任何开发资源。

## 三、 当前阶段目标：Phase 3 日常账房模块（mod-finance）

### 3.1 目标具体怎么做（实施方案）
1. **扩展模块注册表**：在 `ModRegistry` 登记日常账房，接入 `/finance` 路由、导航和设置开关。
2. **新增 mod-finance 独立目录**：schema、Dexie v4 表、store、页面和统计纯函数都放在 `src/mods/mod-finance/`。
3. **先做纯记录闭环**：快速记账 → 分类筛选 → 编辑/删除 → 月度汇总 → 近 7 日趋势 → 消费结构占比 → 选择性导入旅行花费。

### 3.2 细节要求（Specs & Edge Cases）
- **细节 A（快速记账）**：每条记录含 nanoid、`yyyy-MM-dd` 日期、整数分金额、分类、备注和来源；不接任何支付、转账、银行卡或金融 API。
- **细节 B（统计）**：月度合计、近 7 日趋势、分类占比全部由本机记录现算，不落盘聚合值；分类金额之和必须等于总额。
- **细节 C（旅行账单联动）**：可从私人旅行花费选择性导入；来源用 `sourceTripId + sourceExpenseId` 去重；导入只读旅行表，不修改旅行账本，不重复计金额。
- **细节 D（边界）**：所有数据 100% 本机 IndexedDB；无账号、无云端、无遥测、无支付；删除记录只删 finance 表，不影响旅行。

## 四、 验收标准（Definition of Done - 必须全部满足才算完成）

1. **功能达标**：`/finance` 可快速记账、编辑、删除、按日期/分类筛选，统计结果实时更新。
2. **金额正确**：金额一律整数分；月度总额、分类合计、近 7 日趋势守恒；非法金额和空分类不写入。
3. **联动安全**：旅行花费导入可去重，重复导入不重复计数；导入过程不修改 `trips` 表。
4. **防回归测试（铁律）**：新增 `test-finance`，并完整运行现有 14 个测试脚本与生产构建，全部通过。
5. **UI 达标**：手机窄屏可操作，空状态、筛选和统计展示清晰。
