## 一、 全局北极星与架构铁律（固定框架，留有扩展空间）

### 1.1 产品终极定位
**本地优先的模块化个人生活系统（Local-First Modular Life OS）**。采用 **“宿主微内核 + 共享能力引擎 + 可插拔业务模块 (Mod)”** 三层插座架构：
- **宿主层 (`src/core/`)**：IndexedDB 本地存储、主题外观、全局备份、模块开关注册表 (`ModRegistry`)。
- **共享引擎层 (`src/engines/`)**：
  - `LedgerEngine`（通用记账、分类、分摊、消费成分结构占比计算）
  - `TimelineEngine`（跨天行程、单日时间轴计划、50步撤销栈）
  - `NoteEngine`（结构化备忘录、每日复盘模板、自动保存）
  - `LanShareEngine`（手机安装 App 后的面对面局域网扫码分享与组团）
- **业务模块层 (`src/mods/`)**：按需插拔，界面统一，数据默认隔离、支持按需跨模块联动。

### 1.2 全局禁区（负面清单 / Anti-Goals）
- 🚫 **绝不碰金融与资金流**：只做纯数字记录、清结算建议与消费成分分析，不接任何支付接口。
- 🚫 **绝不搞云端与重型服务端**：100% 本机存储，无账号、无遥测。
- 🚫 **停止过度设计团队拓扑**：团队协作仅作为“手机装好 App 后面向亲友的面对面扫码组团工具（隶属旅行模块）”。**严禁**再往“家里放手机当算力主机、外网远程控制、复杂离线文件传输”方向投入任何开发资源。

## 三、 当前阶段目标：Phase 2 日常规划模块（mod-daily）

### 3.1 目标具体怎么做（实施方案）
1. **建立最小 ModRegistry**：为旅行和日常规划登记模块清单、路由和导航入口；暂不物理搬迁旅行模块，避免破坏已验收功能。
2. **新增 mod-daily 独立目录**：数据 schema、Dexie 表、store、页面和组件都放在 `src/mods/mod-daily/`，默认本地存储、无账号、无云端。
3. **先做最小可用闭环**：按日期加载当天计划 → 增删改任务与时间块 → 随手备忘自动保存 → 三问复盘保存 → 切换日期数据隔离。

### 3.2 细节要求（Specs & Edge Cases）
- **细节 A（每日计划）**：每天一条 `daily-day.v1` 记录；任务包含 nanoid、标题、可选起止时间、完成状态；任务排序稳定；日期必须是 `yyyy-MM-dd`，时间必须是 `HH:mm`。
- **细节 B（随手备忘录）**：当天自由文本，停止输入后自动保存；空文本合法；切换日期不能串数据。
- **细节 C（结构化复盘）**：三问固定为「今天做得好的」「今天卡住的」「明天最重要的一件事」；允许留空，保存后重新打开仍能恢复。
- **细节 D（模块边界）**：日常模块不读取旅行私人数据，不写旅行表；旅行模块不因 Phase 2 改动而回归；不提前实现 Phase 3 记账。

## 四、 验收标准（Definition of Done - 必须全部满足才算完成）

1. **功能达标**：`/daily` 页面可按日期新增、编辑、完成、删除任务；备忘自动保存；复盘三问保存后可恢复。
2. **边界防守**：特殊字符、Emoji、多行文本、空内容、日期切换和非法 schema 输入不崩溃、不静默写坏数据。
3. **模块化边界**：ModRegistry 可登记/开关模块；`mod-daily` 代码位于 `src/mods/mod-daily/`；旅行模块回归通过。
4. **防回归测试（铁律）**：新增 `test-daily` 脚本，并完整运行现有 11 个测试脚本与生产构建，全部通过。
